# 手机看板（实验性辅助脚本）

在手机浏览器里看这个项目的看板，把桌面屏幕腾出来。

> **这不是本项目的正式功能**，是一个零依赖的辅助脚本，按需自取、不保证维护。
> 正式做法应该是把 HTTP 服务并进 `app/src-tauri`（复用已有的会话读取和用量统计），
> 而不是像这里一样另起一个 Node 进程。它之所以存在，是因为**先验证体验再决定要不要正经做**。
>
> 仅在 Windows 上验证过。「聚焦终端」依赖 Win32，其余部分（看板显示）跨平台应该没问题。

## 跑起来

需要 **Node 20.11+**（用到 `import.meta.dirname`；版本不够会在启动时明确报出来）。
`build.mjs` 会通过 `npx` 临时取用 esbuild，除此之外无依赖。

```bash
cd tools/phone
node build.mjs     # 首次必须跑：生成降级版 JS（见下方「浏览器兼容」）
node server.mjs
```

> 忘了跑 `build.mjs` 也能启动，但启动时会警告：旧安卓浏览器会白屏。

启动时会打印手机该用的地址，形如：

```
手机   http://<你的内网IP>:7788/?t=<令牌>
```

手机需与电脑在同一 WiFi。**书签用带 `?t=` 的那条**，才能点卡片切窗口（见「操控」一节）。

停止：`Ctrl+C`。若在后台跑：

```bash
powershell -NoProfile -Command "Get-NetTCPConnection -LocalPort 7788 -State Listen | ForEach-Object { Stop-Process -Id \$_.OwningProcess -Force }"
```

> 内网 IP 可能被路由器重新分配。嫌烦就在路由器里给这台机器绑个静态 DHCP 租约。

可调项：`PORT=8080`、`MAX_AGE_H=48`、`UI_DIR=...`、`LEGACY=0`。

## 建议在手机上这样用

1. 浏览器菜单 →「添加到主屏幕」，之后从图标进入，没有地址栏，接近全屏 app。
2. **防熄屏**：设置 → 开发者选项 →「充电时保持唤醒」。
   （网页的 Wake Lock API 需要 HTTPS，纯 HTTP 局域网用不了，只能靠系统设置。）
3. 插着充电，找个支架立在视线边缘。
4. **把屏幕亮度调到最低。** 见下面「省电」一节——这一条的收益比所有代码优化加起来都大。

## 它是怎么工作的

零依赖 Node HTTP 服务，直接托管仓库里现成的 UI（`app/ui/`），
再注入一个伪造的 `window.__TAURI__`，把 UI 的 `invoke()` 接到 REST 上。
所以 **UI 代码一行都没改**，你在手机上看到的和桌面看板是同一份。

```
GET /                 注入垫片后的 index.html
GET /src/*            原样托管仓库里的 main.js / styles.css
GET /api/sessions     读 ~/.claude/monitor/*.json，过滤后返回
GET /api/rate-limits  读 ~/.claude/monitor/usage-limits.json
GET /api/usage        桩，恒返回 0（UI 优先用 rate-limits，一般走不到）
GET /api/debug        过滤统计，排查用
```

## 僵尸会话过滤

`~/.claude/monitor/` 里积了 130 个状态文件，绝大多数是残留（会话异常退出时不会删）。
三道过滤后剩 7 个，与实际在跑的会话吻合：

| 过滤 | 剔除 |
|---|---|
| 没有 `status` 字段（如 `usage-limits.json`） | 1 |
| 终端进程已退出（`process.kill(pid, 0)` 探测） | 114 |
| 超过 8 小时没更新（`MAX_AGE_H` 可调） | 8 |

第三道是必须的：实测有一批 100～600 小时前的化石，终端进程恰好还活着
（或 pid 被系统回收给了别的进程），光靠 pid 判不掉。

**注意这与正式版不等价。** 正式版在 Rust 里用 Win32 `IsWindow` + HWND 回收校验
（`app/src-tauri/src/lib.rs:42`），精确；这里是近似。原型够用即可。

调参：

```bash
MAX_AGE_H=24 node server.mjs     # 放宽到 24 小时
PORT=8080 node server.mjs        # 换端口
```

## 浏览器兼容（踩过的坑，别删 main.legacy.js）

仓库的 `app/ui/src/main.js` 用了 **ES2020** 语法（`?.` × 9、`??` × 2），需要 **Chrome 80+**。
旧浏览器在**解析阶段**就失败，JS 一行不跑，页面只剩静态 HTML——
现象是「只有 CLAUDE·MON 标题和齿轮按钮」，很容易误判成空页面。

所以本原型不加载 `main.js`，而是加载 `main.legacy.js`：esbuild 降级到 **ES2015 + IIFE**
（连 `<script type="module">` 都不用，那个本身要 Chrome 61）。

仓库 UI 改动后需重新生成：

```bash
node build.mjs
```

`build.mjs` 做两件事：在源码**副本**上打补丁（仓库的 `main.js` 一个字节都不动），然后 esbuild 降级。
补丁匹配不上会**直接报错退出**——宁可构建失败，也不要悄悄产出一个「看着正常但补丁没生效」的版本。

当前补丁（都是为省电，详见「省电」一节）：

| 补丁 | 原因 |
|---|---|
| `setInterval(tick, 1000)` → `6000` + `document.hidden` 门控 | 每次 XHR 都要把 WiFi 芯片从省电态唤醒一轮，频率直接决定射频占空比。看板只是「瞄一眼」，6s 够用 |
| 加 `visibilitychange` 监听 | 回到前台立刻补一次，不用干等一个周期 |
| `setInterval(tickUsage, 30000)` 同样加门控 | 息屏时用量条也没必要醒 |

`POLL_MS=10000 node build.mjs` 可改轮询间隔（默认 6000）。

> 门控用的是 `document.hidden !== true`：老浏览器上这个属性可能是 `undefined`，
> 那就当页面可见照常轮询——降级成旧行为，而不是永远不刷新。

想用原版对比：`LEGACY=0 node server.mjs`（在旧手机上会白屏，这是预期的）

### 实测设备

| 设备 | 内核 | 结果 |
|---|---|---|
| 某 Android 5.1 机型自带浏览器 | AppleWebKit/534.30（2011 年内核，UA 里的 `Chrome/50` 是**伪造**的） | ✗ 连箭头函数都不认 |
| 同机装 Chrome 75 | Blink 75 | ✓ 靠 `main.legacy.js` 正常显示 |
| 桌面 Chrome | 最新 | ✓ |

> 老设备上如果只看到标题栏和齿轮按钮、卡片区一片空白，基本就是 JS 没跑起来。
> 别急着查后端——先确认加载的是 `main.legacy.js`，以及 `node build.mjs` 跑过了。

Chrome 75 缺的几个 CSS 特性已在 `MOBILE_CSS` 里补掉：

| 缺失特性 | 需要版本 | 症状 | 补法 |
|---|---|---|---|
| flex `gap` | 84 | 卡片挤成一坨 | 改用 `#cards > * + * { margin-top }`，并把 `gap` 置 0。不做特性检测，所有浏览器走同一路径，结果一致 |
| `100dvh` | 108 | 底部被地址栏盖住 | 不用 `vh` 也不用 `dvh`，改 `height: 100%` 逐级继承——所有浏览器行为一致，最稳 |
| `color-mix()` | 111（样式表 7 处） | 卡片背景声明整条失效、显得扁平 | `@supports not (...)` 里给 `.row` 补个底色，新浏览器不受影响 |

`color-mix` 剩余几处（焦点环、状态芯片底色、安装按钮）纯装饰，未补。

## 省电

常亮当看板，电量掉得比想象快。按实际影响排序：

**1. 屏幕背光（占大头，代码管不了）**
老机器是 LCD 背光，全亮约 400~700mW，光它自己就能在十几小时里抽干一块已经衰减的电池。
**把亮度调到最低**，收益超过下面所有代码优化的总和。暗色主题在 LCD 上不省电（没有 OLED 的黑点熄灭效应）。

**2. 常驻 CSS 动画（已在 `MOBILE_CSS` 里关掉）**
`styles.css` 有 4 个 `infinite` 动画：LED 呼吸、WAIT 告警、标题栏信号点脉冲、空态光标。
styles.css:293 那句「只动 opacity → GPU 合成层，不触发重绘」是**为桌面写的**，
目的是防止透明置顶窗口闪屏；放到手机上结论反过来——只要还有一个 infinite 动画在跑，
合成器就永远进不了空闲，GPU 和一个 CPU 核被持续唤醒，7 张卡就是 7 个动画层。
Chrome 75 在这类老 GPU 上还未必真走得上合成路径，退化成全量重绘只会更贵。

代价：WAIT 的 LED 不再闪。**可以接受**，因为状态本来就靠颜色 + `WAIT`/`RUN` 文字标签区分；
而且「刚变成 WAIT」的那下醒目提示走的是 `.row.flash-wait`（一次性放 3 遍），是一次性动画，不受影响。

**3. 轮询频率 + 条件请求**
1s → 6s，并加可见性门控（切后台/熄屏彻底停表，浏览器自己那套后台节流只是把定时器拉长、不会停）。
外加 `/api/sessions` 和 `/api/rate-limits` 上 ETag：状态文件的 `updated_at`
只在 hook 事件时变、不是心跳，所以没会话在动时每次拿到的 JSON 逐字节相同，直接回 304 空体
（实测 3245 字节 → 0 字节），省掉传输、`JSON.parse` 和一次全量 render。

代价：卡片上的秒表变成 6 秒一跳。读数本身不会错（前端按 `running_since` 算），只是刷得粗。

> ETag 的 200 响应仍然发 `no-store`，**不要改成 `no-cache`**：那样浏览器会自己存一份，
> 并在下次请求时**追加**它自己的 `If-None-Match`；XHR 的 `setRequestHeader` 是逗号拼接语义，
> 两个值拼一起就永远等不上服务端算的那个，304 一次都不会命中。
> 这里的 ETag 是应用级的——垫片自己存 etag 和上次解析结果，不依赖浏览器 HTTP 缓存。

> 排错工具：页面注入了纯 ES5 的错误上报（`window.onerror` + `unhandledrejection` + 存活信标），
> 报错会画成红底页并 POST 到 `/api/log`，直接打在服务端控制台——手机上没 devtools，靠它定位。
> 垫片本身必须是 ES5，否则它自己先挂，连"为什么挂"都报不出来（第一版就栽在用了 `async/await`）。

## 操控：点卡片切到该终端

手机上点卡片 → PC 上那个终端窗口跳到前台。解决「6 个平铺窗口里找不着是哪个」。

启动时打印的带 `?t=` 那条 URL 才有操控能力，**手机书签要用它**：

```
http://<你的内网IP>:7788/?t=<令牌>
```

不带令牌也能正常看，只是点卡片会提示「操控未启用」——**明确告诉你，而不是默默没反应**。

令牌存在 `token.txt`，首次启动随机生成后复用，所以重启服务不用改书签。想换令牌就删掉这个文件重启。

**为什么只有这个接口要令牌**：只读接口泄露的是信息，而聚焦是**往你 PC 上动手**，同网段谁都能调就太过了。

实现绕了一圈：Node 调不了 Win32，所以 `focus.ps1` 用 PowerShell P/Invoke 复刻了
`claude-code-monitor` 的 `lib.rs:307 focus_hwnd_windows()`。其中「模拟 ALT 抬起」和
`AttachThreadInput` 两步不能省——Windows 有前台锁，非前台进程直接调 `SetForegroundWindow`
会被静默忽略，只闪一下任务栏。

安全上：`session_id` 先过 `^[A-Za-z0-9_-]{1,128}$` 白名单再拼路径，
交给 PowerShell 的只有一个校验过的整数 HWND，不拼任何字符串进命令行。

### 没做的第二档：发送输入

mac 上 `write_tty` 能直接往 `/dev/ttys00X` 写字符串，Windows 的 ConPTY 没有对应的可写设备，
只能「聚焦窗口 + `SendInput` 合成键盘事件」。风险三条，所以没做：

- 合成按键进的是**当前前台窗口**，聚焦一旦失败就打到别处去了
- 卡片上的 `message` 被 hook 截断到 120 字符，**对没读全的授权请求点「允许」是真风险**
- 手机上看到的是最多 3 秒前的快照，点下去时状态可能已经变了

## 故意没做的事

- **右键菜单里的「打开项目目录 / 移除卡片」仍是空操作**，只接了聚焦。
- **只读接口无鉴权、全程明文 HTTP**。同网段任何设备都能看到你的项目名、git 分支、prompt 片段。
  你的 WiFi 当前被 Windows 归类为「公用网络」，在外面（公司 / 咖啡厅）别开。
- **不做 token 用量统计**（`/api/usage` 是桩）。限额百分比是真的，走 `usage-limits.json`。
- 桌面端那些窗口/托盘功能（置顶、隐藏、开机自启）在手机上全是空操作，按钮已用 CSS 藏掉。

## 用两天后，回答这四个问题

1. 手机屏幕上，7 张卡扫一眼能分清谁在 WAIT 吗？字够大吗？
2. 常亮一夜，耗电和烧屏能接受吗？（先按「省电」一节调完再判断）
3. 支架摆哪儿既看得见又不碍事？
4. **你会真的去看它吗？**

第 4 个最关键。如果答案是「装完就忘了」，那就别做正式版了——
先验证再投入，这正是这个脚本存在的意义。
