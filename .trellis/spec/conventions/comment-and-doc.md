# 注释与文档：注释是决策记录

这是本仓库最鲜明的特征，也是最该守住的一条。**这里的注释不是解释代码在做什么，而是记录"为什么非得这么写"**——因为这个项目里绝大多数代码的形态都是被平台坑、并发窗口、旧浏览器、用户环境逼出来的，注释一丢，下一个人（或下一个 AI）就会"顺手简化"掉必需的绕弯。

---

## 三种必须写的注释

### 1. 反直觉代码的辩护（最重要）

凡是代码看起来多余、绕弯、或"明显可以更简单"，必须写清简化会坏在哪。

```rust
// app/src-tauri/src/lib.rs:50 —— 没有这段注释，下一个人一定会把 win_pid 校验删掉
// IsWindow 还不够：Windows 会把关掉窗口的 HWND 号回收给别的窗口
// （重启后尤为普遍），于是一堆早已关闭的会话卡片赖着不走。
```

```js
// tools/phone/server.mjs:220 —— 解释为什么不用 fetch
// 用 XHR 不用 fetch：这段垫片必须能在最旧的浏览器上跑起来，
// 否则连"为什么跑不起来"都上报不出去（第一次就栽在这——垫片用了 async/await，
// 旧浏览器解析阶段就挂了，页面只剩静态 HTML，看着就是"空页面"）。
```

```js
// app/ui/src/main.js:162 —— 注释直接点名"这才是刷屏的根因"
// 首次见到该会话：静默打底，绝不通知。否则「开板/重启前就已完成」或「晚一帧才进列表」的
// 会话会被误当成刚刚完成而误报——这才是刷屏的根因（重启一次攒一条）。
```

**判据**：如果删掉这段代码，功能表面上还能跑，只是某个边界情形会坏 —— 那就必须有注释说明那个边界情形。

### 2. 文件头说明块

每个非平凡文件开头一段块注释，交代 4 件事：**这是什么 / 怎么用 / 为什么这样设计 / 已知取舍**。范本：

- `hooks/emit-status.mjs:1-10` —— 用法（hook 里怎么配）、stdin 契约、"纯 Node、无第三方依赖"
- `app/src-tauri/src/install.rs:1-15` —— "为什么放在 App 里"（用户老忘第二步）+ **两个刻意的设计**（`include_str!` 内嵌、不 spawn node）
- `hooks/statusline-bridge.mjs:1-13` —— 为什么必须包一层而不能直接顶掉用户的 statusline
- `tools/phone/server.mjs:12-22` —— **安全模型（重要，别想当然）** + **已知取舍** 两个小标题

"已知取舍"这一节是硬要求：凡是原型/近似实现，必须自己先说破哪里不精确。例：

```js
// tools/phone/server.mjs:18
// 已知取舍：
//   - 僵尸会话剔除是近似的（pid 存活 + 时效闸门），不如 app/src-tauri 里
//     那套 Win32 IsWindow + HWND 回收校验精确。
```

### 3. 魔数与阈值的来历

任何常量都要说清数值是怎么来的，尤其是"为什么不是更小/更大的那个值"。

```js
// tools/phone/server.mjs:46
// 时效闸门：状态文件超过这个时长没更新就当它是残留。
// 设 24 而不是 8：实测化石都在 105h 以上、真实会话都在 7h 以内，中间空档很大，
// 24h 一样能切干净，却能保住「早上跑的、晚上回家才看」的会话——8h 会把它们误删。
const MAX_AGE_MS = Number(process.env.MAX_AGE_H || 24) * 3600 * 1000;
```

其他范例：`hooks/emit-status.mjs:154` 的 `TAIL_BYTES = 1MB`、`tools/phone/build.mjs:22` 的 `POLL_MS = 6000`（解释到"WiFi 芯片占空比"这一层）、`app/ui/src/main.js:623` 的 `30000`。

## 格式

- 中文注释，`——` 或 `：` 引出解释，不用 `TODO:` 堆积（真有待办写进 [../code-smells.md](../code-smells.md)）。
- Rust 公开函数用 `///` 文档注释，一句话说清职责 + 边界；私有辅助函数也写（见 `lib.rs` 里每个 `fn` 上方都有）。
- JS 用 `//`；分区用 `// ==== 区块名 ====` 分隔（`app/ui/src/main.js` 全文按此分了 8 个区块，是这个 600 行单文件还能读的唯一原因）。
- 引用具体位置时写 `文件:行号`（如 `styles.css:293`、`lib.rs:307`），跨文件说明必须给出路径，不要只说"另一处"。
- 注释里出现结论性判断时，写上它的适用范围。范例 `tools/phone/server.mjs:394`：

  ```
  styles.css:293 那句「只动 opacity → GPU 合成层，不触发重绘」是为桌面写的，
  目的是防止透明置顶窗口闪屏；结论在手机上反过来——只要还有一个 infinite 动画在跑，
  合成器就永远进不了空闲。
  ```

## README 同步（硬规）

`README.md` 是这个项目对外的唯一说明书，它承诺的功能必须真实存在。

- 改了功能、hook 事件映射、目录结构、安装步骤 → 同一个 commit 里改 README 对应段落。
- 尤其这 4 处容易漏：
  - `## 亮点` 的功能清单
  - `## 工作原理` 的 hook → 状态映射表（必须与 `hooks/status-logic.mjs` 的 `STATUS_BY_EVENT` 一致）
  - `## 使用` 的操作清单
  - `## 目录结构` 树
- **禁止**在 README 里写还没实现的功能（当前已有违例，见 [../code-smells.md](../code-smells.md)）。
- `## 隐私说明` 里列举的落盘字段必须与 `hooks/emit-status.mjs` 的 `record` 对象一致。
