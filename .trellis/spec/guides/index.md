# 思维指南

> **用途**：扩展思考面，逮住那些"没想到"的东西。
>
> 大多数 bug 和技术债来自"没想到"，不是来自技术不行。

| 指南 | 作用 | 什么时候读 |
|---|---|---|
| [跨层思维指南](./cross-layer-thinking-guide.md) | 把 hook → JSON → Rust → UI 的数据流走一遍 | 改契约字段、加状态/事件/命令时 |
| [代码复用思维指南](./code-reuse-thinking-guide.md) | 识别重复；管住本项目三组**刻意的**跨运行时重复 | 改常量、抄代码、建工具函数时 |

这两份是"想什么"，[../index.md](../index.md) 指向的各层规范是"怎么写"。

## 触发条件速查

### 该想跨层问题了

- [ ] 要往 `~/.claude/monitor/<id>.json` 加/改字段
- [ ] 要加 hook 事件、状态值或 Tauri 命令
- [ ] 同一份数据有多个消费者（当前读者：Rust 看板、UI、手机原型服务端）
- [ ] 不确定某段逻辑该放哪一层
- [ ] UI 代码开始直接读一个"我猜它一定有"的字段
- [ ] 要新增一条写盘路径（想过并发了吗？）

→ 读 [跨层思维指南](./cross-layer-thinking-guide.md)

### 该想复用问题了

- [ ] **要改任何常量或配置值** ← 先 grep
- [ ] 在写和已有代码相似的东西
- [ ] 同一个模式出现第 3 次（当前已知：`focusable` 判定抄了 3 遍）
- [ ] 要给多个地方加同一个字段
- [ ] 要新建一个工具函数 ← 先搜有没有
- [ ] 在动 `install-hooks.mjs` / `install.rs` / `focus.ps1` / `sanitize_id` 这些**有孪生实现**的文件

→ 读 [代码复用思维指南](./code-reuse-thinking-guide.md)

## 改任何值之前的铁律

```bash
grep -rn "要改的值" hooks/ install/ app/ tools/ README.md
```

这一条习惯挡掉了这个项目里最大一类 bug。本仓库"一个值散在多处"的完整清单见 [代码复用思维指南](./code-reuse-thinking-guide.md#铁律改任何值之前先搜)。

最常被忘的三个：**版本号（3 处）**、**hook 事件表（3 处）**、**`#cards` 的 gap（CSS + JS 各一处）**。

## 验证 AI 交叉评审结果时

这个仓库的注释密度很高，而且"看起来多余"的代码基本都有注释说明为什么必需。所以：

- **改之前先读注释**。评审说某段是冗余/bug，而注释给了理由 → 要能指出注释哪里错了，否则按注释走。
- 本项目最常见的三类评审假阳性（含判据）见 [跨层思维指南](./cross-layer-thinking-guide.md#验证-ai-交叉评审结果时)：信任边界混淆、忽略设计注释、把刻意的跨运行时重复报成"应该抽取"。
- 经验值：给 AI 评审留约 1/3 的假阳性预算，每条 CRITICAL/WARNING 都对着代码核一遍再排优先级。

## 怎么用这个目录

1. **写代码前**：扫一眼相关的那份指南。
2. **写的过程中**：觉得重复或复杂了，回来查。
3. **修完 bug 后**：把新学到的"没想到"补进对应指南（真正的规范补进各层 spec，具体待办补进 [../code-smells.md](../code-smells.md)）。

**核心信条**：30 分钟的思考省下 3 小时的调试。
